# Настройка сайта Stakeholder Communication

Сайт состоит из пяти страниц:

| Файл | Страница |
|---|---|
| `index.html` | Stakeholder Analysis: кейсы с блоками Team workspace под каждым кейсом |
| `cna.html` | Comprehensive Needs Analysis: поля для ответов команды и выгрузка PDF |
| `experts.html` | Working with Experts: работа с экспертами по дисциплине, поля для ответов команды и выгрузка PDF |
| `kanban.html` | Project Kanban команды |
| `admin.html` | Панель преподавателя: код курса, компании, команды, список студентов |

Вход на все страницы — по email и паролю. Студент регистрируется сам и вводит код курса. В команду его распределяет преподаватель в Teacher panel; до этого студент видит экран «Waiting for your team». Каждая команда видит только свои CNA и Kanban. Преподаватель видит всё.

## Часть 1. Firebase (один раз, ~15 минут)

Откройте https://console.firebase.google.com → проект **stakeholders-b7fd9**.

### 1.1. Включить вход по email и паролю
1. Слева: **Build → Authentication** → **Get started** (если раздел ещё не открывался).
2. Вкладка **Sign-in method** → **Email/Password** → включите первый переключатель **Email/Password** (второй, «Email link», не нужен) → **Save**.
3. Вкладка **Settings → User actions**: флажок **Enable create (sign-up)** должен быть включён — иначе студенты не смогут зарегистрироваться.

### 1.2. Разрешить адреса сайта
**Authentication → Settings → Authorized domains → Add domain**, добавьте:
- `oletol.github.io` — адрес сайта на GitHub Pages;
- `127.0.0.1` — для предпросмотра в VS Code (Live Server).

> **Только адреса @misis.ru.** Этот список не ограничивает почту студентов: он задаёт адреса сайтов, на которых разрешён вход. Ограничение по почте уже встроено в сайт и в правила базы (шаг 1.3). Регистрация принимает только адреса, заканчивающиеся на `@misis.ru`, включая поддомены вроде `@edu.misis.ru`. Аккаунт с другой почтой не получит доступа к курсу даже с верным кодом. Ваш собственный аккаунт преподавателя может быть с любой почтой.

### 1.3. Правила безопасности базы
1. **Build → Realtime Database → вкладка Rules**.
2. Удалите всё содержимое и вставьте целиком содержимое файла `database.rules.json`.
3. Нажмите **Publish**.

Проверка (по желанию): кнопка **Rules Playground** → Type: *read*, Location: `/cna/g1`, Authenticated: *выкл.* → **Run** → должно быть **Denied**.

> Важно: если база создавалась в «тестовом режиме», старые правила перестают работать через 30 дней после создания, и сайт перестаёт сохранять данные. После публикации новых правил это ограничение снимается.

### 1.4. Аккаунт преподавателя
1. **Authentication → Users → Add user** → ваш email и пароль → **Add user**.
2. В списке пользователей скопируйте ваш **User UID** (длинная строка букв и цифр).

### 1.5. Права преподавателя
1. **Realtime Database → вкладка Data**.
2. Наведите курсор на корневую строку (адрес базы) → нажмите **+**.
3. **Key:** `admins`. Нажмите **+** рядом с ним, чтобы добавить вложенную запись.
4. Во вложенной записи: **Key:** ваш UID, **Value:** `true` → **Add**.

Должно получиться:
```
admins
  └─ ваш UID : true
```

### 1.6. Код курса и компании
1. Откройте сайт → войдите своим email и паролем.
2. В строке под меню нажмите **Admin** → откроется **Teacher panel**.
3. **Course code** — придумайте код (не меньше 4 символов), нажмите **Save code**.
4. **Project teams** — для каждой из 5 команд впишите компанию практики (она показывается в шапке команды и в PDF). Например:

| Team | Internship company |
|---|---|
| Group 1 | Компания А |
| Group 2 | Компания А |
| Group 3 | Компания Б |
| Group 4 | Компания Б |
| Group 5 | Компания В |

5. Сообщите студентам адрес сайта и код курса.

### Просмотр работ других команд
**Teacher panel → Viewing other teams' work**: для каждой страницы (Stakeholder Analysis, CNA, Kanban) есть кнопка **Open / Close**.
- **Closed** (по умолчанию): каждая команда видит только свою работу.
- **Open**: у студентов в строке под меню появляются кнопки других команд; чужая работа открывается только для чтения, писать можно только в своей команде. Кнопка **Back to my team** возвращает к своей команде.
- Закрытие действует сразу: студенты, которые смотрели чужую работу, автоматически возвращаются к своей.

### Распределение по командам
1. Студент: **Create an account** → имя, университетская почта (@misis.ru), пароль, код курса → видит экран «Waiting for your team».
2. Вы: **Teacher panel → Students**. Новые студенты стоят в начале списка со статусом **Waiting for team**. Выберите команду в колонке **Team**.
3. У студента сайт открывается автоматически (или при следующем входе).
4. Перевести студента в другую команду можно в любой момент там же. Его прежние ответы остаются у прежней команды.

Студент, забывший пароль, нажимает **Forgot password?** на странице входа. Письмо приходит от `noreply@stakeholders-b7fd9.firebaseapp.com` — попросите проверить папку «Спам».

## Часть 2. Visual Studio Code и GitHub

### 2.1. Подготовка (один раз)
1. Установите **Git**: https://git-scm.com.
2. В VS Code откройте **Extensions** (Ctrl/Cmd + Shift + X), установите **Live Server** (автор Ritwick Dey).

### 2.2. Получить репозиторий
1. VS Code → **Source Control** (значок ветки слева) → **Clone Repository**.
2. Вставьте `https://github.com/Oletol/stakeholders.git`, выберите папку на компьютере.
3. При запросе войдите в GitHub.

### 2.3. Добавить новые файлы
Скопируйте в папку репозитория всё содержимое папки `stakeholders-site` (с заменой `index.html`):
```
index.html  cna.html  kanban.html  admin.html
database.rules.json  SETUP.md  LICENSE
assets/  (db.js, group.js, cna.js, experts.js, kanban.js, seminar.js, admin.js, site.css, vendor/)
```

### 2.4. Посмотреть перед публикацией
Правый клик на `index.html` → **Open with Live Server** (или кнопка **Go Live** внизу справа). Сайт откроется по адресу `http://127.0.0.1:5500`.

Двойной щелчок по файлу в Finder **не подойдёт**: при открытии страницы как файла вход и поля ответов не работают. Сайт сам покажет предупреждение об этом.

### 2.5. Опубликовать
1. **Source Control** → в поле сообщения напишите, например, `Add login, CNA workspace and Kanban` → **Commit**.
2. **Sync Changes** (или **Push**).
3. Через 1–2 минуты изменения появятся на `https://oletol.github.io/stakeholders/`.

Если GitHub Pages ещё не включён: репозиторий на github.com → **Settings → Pages** → Source: **Deploy from a branch** → Branch: **main**, папка **/(root)** → **Save**.

### 2.6. Дальнейшие правки
Измените файл → посмотрите через Live Server → Commit → Sync Changes.

## Где хранятся данные

| Путь в базе | Что хранится | Кто видит |
|---|---|---|
| `users/` | имя, email, команда студента | студент — себя, преподаватель — всех |
| `members/g1…g5` | состав команд | все зарегистрированные |
| `groups/gN/profile` | профиль команды для PDF | команда и преподаватель |
| `cna/gN` | ответы CNA | команда и преподаватель |
| `kanban/gN` | задачи Kanban | команда и преподаватель |
| `stakeholder/gN` | ответы команды по кейсам Stakeholder Analysis | команда и преподаватель |
| `seminarWorkspace/groupN` | архив: тексты из прежней версии страницы Stakeholder Analysis | показываются в Teacher panel |
| `config/` | код курса, компании команд, открытый просмотр (`config/share`) | код — только преподаватель |
| `admins/` | UID преподавателей | только преподаватель |

Второго преподавателя можно добавить так же, как в шаге 1.5.

## Как устроены страницы с ответами (для следующих разделов)

Поля ответов, матрицы, RACI и выгрузка в PDF работают на общем модуле `assets/workspace.js`. У каждой страницы есть только своя «схема» заданий:

| Страница | Схема | Ветка в базе |
|---|---|---|
| Stakeholder Analysis | `assets/stakeholder.js` | `stakeholder/` |
| Comprehensive Needs Analysis | `assets/cna.js` | `cna/` |

Новый раздел (например, Instructional Design, Communication with Experts, Material Design) добавляется так: новая HTML-страница + файл схемы + одна строка в правилах базы (по образцу `cna`). Готовые типы блоков:
`fixed` (таблица с заданными строками), `rows` (таблица с добавлением строк), `fields` (текстовые ответы), `checks` (чек-лист), `assess` (оценка стейкхолдеров), `plots` (матрицы и сводка), `raci` (RACI с проверкой).
